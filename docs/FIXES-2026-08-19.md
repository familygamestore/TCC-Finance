# Fixes & Upgrade — 2026-08-19

Dilakukan setelah audit menyeluruh (CSS, TypeScript, build, alur data, loading state).
Verifikasi sebelum & sesudah: `npm run typecheck` ✅ 0 error, `npm run build` ✅ sukses
(12/12 route), parsing `globals.css` ✅ 0 error, sintaks `Code.gs` ✅ valid.

## 1. Bug fix — flash "Belum ada transaksi" di /transactions
`app/transactions/page.tsx`: state `ready` sebelumnya di-set `true` langsung di
`useEffect`, tidak menunggu fetch data selesai — sekilas muncul teks
"Belum ada transaksi" sebelum data asli tampil. Diganti jadi state `loading`
yang benar-benar mengikuti selesainya `api.getTransactions()`, ditambah baris
spinner "Memuat transaksi…" (konsisten dengan pola di EventList) dan pesan
error yang sekarang ditampilkan ke user (sebelumnya error di-swallow).

## 2. Cache ringan di backend (Apps Script) — data terasa lebih cepat
`apps-script/Code.gs`: `getSheetAsObjects_()` sekarang cache hasil baca sheet
selama 20 detik lewat `CacheService`, di-invalidate otomatis begitu ada
create/update/delete pada sheet terkait (hook di `appendRowFromObject`,
`updateRowById_`, `deleteRowById_`, dan `updateRequestStatus_`). Sheet yang
berkaitan dengan auth/sesi/permission (`USERS`, `AUTH_USERS`, `BRAND_USERS`)
sengaja **tidak** di-cache demi keamanan (perubahan password/akses harus
langsung berlaku). Efeknya: baca berulang (mis. dashboard yang baca
INCOME+EXPENSE+EVENTS sekaligus) jauh lebih cepat, tanpa membuat data terasa
basi setelah user melakukan aksi.

## 3. Timeout di fetch frontend
`frontend/lib/api.ts`: semua request ke `/api/apps-script` sekarang punya
timeout 15 detik (`AbortController`). Sebelumnya kalau backend lambat/hang,
tombol bisa "menggantung" tanpa kepastian. Sekarang muncul pesan error yang
jelas ("Server tidak merespons (timeout)." / "Tidak bisa terhubung ke
server.").

## 4. Konsistensi loading state
- `.loading` (CSS) sekarang punya spinner, sama seperti `.landing-loading`.
- Halaman login Admin & Super Admin sekarang pakai spinner saat "Memeriksa
  sesi…", bukan teks polos.
- Duplikat `@keyframes spin` (didefinisikan 2x) dirapikan jadi satu.

## 5. Bug fix — sidebar mobile menimpa tombol hamburger
`globals.css`: `.mobile-menu-button` dinaikkan dari `z-index:70` →
`z-index:1010`, `.nav-backdrop` dari `z-index:59` → `z-index:990`. Sebelumnya
override global `.app-sidebar{z-index:1000}` di akhir file membuat drawer
sidebar mobile menimpa tombol hamburger saat dibuka, sehingga tombol itu
tidak bisa diklik ulang untuk menutup drawer.

## 6. Badge status berwarna
`.tag.upcoming/.pending`, `.tag.ongoing/.approved`, `.tag.completed`,
`.tag.cancelled/.rejected` ditambahkan di `globals.css`. Sebelumnya badge
status Event Hub & Riwayat Pengajuan tampil polos/abu-abu semua.
`app/requests/page.tsx` diupdate supaya class badge status dinamis mengikuti
nilai status (lowercase).

## 7. Bersih-bersih kode
Menghapus 4 file komponen yang sudah tidak dipakai sama sekali (leftover
refactor, tidak ter-import di manapun): `components/events/EventsPage.tsx`,
`components/events/components/EventRow.tsx`, `PageHeader.tsx`, `FormField.tsx`.

## 8. Proteksi double-klik di tombol ACC/Tolak
`app/super-admin/page.tsx`: tombol ACC/Tolak sekarang disable begitu salah
satu baris sedang diproses (state `busyReq`), diganti tampilan "Memproses…".
Backend sudah aman dari duplikasi (LockService), ini murni perbaikan UX agar
tidak membingungkan.

## 9. Tombol Esc untuk menutup drawer/form
`hooks/useEscapeKey.ts` (baru) dipasang di semua drawer form: Event Hub,
Requests, Cash reconciliation. Tekan Esc sekarang menutup drawer, sama
seperti klik backdrop/tombol ×.

## 10. Modal konfirmasi custom (bukan `window.confirm`)
`hooks/useConfirm.tsx` (baru): dialog konfirmasi hapus yang ikut tema
aplikasi (termasuk dark mode), menggantikan `window.confirm()` bawaan
browser di `super-admin/page.tsx` (hapus transaksi, hapus event) dan
`app/events/page.tsx` (hapus event).

## 11. Halaman error fallback
`app/error.tsx` dan `app/not-found.tsx` (baru): kalau ada error runtime tak
terduga di komponen manapun, user sekarang melihat halaman error yang sesuai
desain aplikasi dengan tombol "Coba lagi"/"Kembali ke Dashboard", bukan layar
kosong/error generik Next.js.

## 12. localStorage dibungkus try/catch
`lib/api.ts`: semua akses localStorage sekarang lewat wrapper `safeStorage`
yang fallback ke penyimpanan in-memory kalau localStorage gagal (browser
privasi ketat/kebijakan perusahaan). Login tetap bisa jalan untuk tab yang
aktif walau localStorage bermasalah.

## 13. Salt pada hash password (backward-compatible)
`apps-script/Code.gs`: `hashPassword_()` sekarang menerima salt opsional.
Password yang di-set/diganti setelah update ini otomatis dapat salt acak
baru (`generateSalt_()`), disimpan di kolom baru `password_salt`. Akun lama
yang belum ganti password tetap bisa login seperti biasa (fallback ke mode
tanpa salt) — **tidak ada akun yang terkunci** oleh perubahan ini. Kolom
`password_salt` otomatis ditambahkan ke sheet `AUTH_USERS` saat
`setupTCCFinanceV8_`/`upgradeTCCFinanceV8_` dijalankan ulang.

## 14. Upgrade dependency (keamanan)
`next` di-upgrade dari `16.2.11` → `16.3.1`, menutup 3 kerentanan **high
severity** (CVE terkait `sharp`/libvips dan path traversal di `postcss`
source map) yang terdeteksi lewat `npm audit`. Hasil setelah upgrade:
**0 vulnerabilities**.

## 15. Search + filter + export CSV di tabel Transaksi
`app/transactions/page.tsx` dirombak: tambah kolom pencarian (ID/nama/
kategori/catatan), filter tipe (Income/Expense), filter rentang tanggal, dan
tombol "Export CSV" (`utils/csvExport.ts`, baru) untuk data yang sedang
ditampilkan/difilter.

## 16. Peringatan sebelum sesi habis
`components/common/SessionExpiryWarning.tsx` (baru), dipasang di root
layout. Muncul otomatis 2 menit sebelum sesi Admin/Super Admin berakhir,
supaya user tidak kehilangan draft form karena tiba-tiba ter-logout.

## Catatan: item yang TIDAK jadi dikerjakan
Rekomendasi "validasi ukuran file bukti sebelum upload" dicabut dari list —
setelah dicek ulang, ternyata **tidak ada fitur upload file bukti di UI
manapun** saat ini (kolom `bukti` di data model belum dipakai form apapun).
Menambahkan validasi untuk fitur yang belum ada hanya akan jadi kode mati;
lebih baik dikerjakan nanti bersamaan saat fitur upload-nya benar-benar
dibangun.

---

**Catatan penting soal "real-time":** arsitektur ini (Next.js → Apps Script
→ Google Sheets) secara desain bukan real-time murni (tidak ada
WebSocket/push). Cache 20 detik di atas mempercepat baca berulang, tapi
setiap aksi tulis (create/update/delete/approve) tetap langsung invalidate
cache sehingga user selalu melihat data terbaru setelah aksi mereka sendiri.
Untuk lihat perubahan dari user lain secara live, halaman masih perlu
di-refresh manual (kecuali halaman Requests yang polling 5 detik untuk status
pengajuan sendiri).
