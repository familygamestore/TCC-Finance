# Perbaikan — 16 Agustus 2026

Ringkasan perubahan yang dilakukan pada paket ini (dibanding versi upload).

## 1. CSS berantakan — ditemukan akar masalahnya

`frontend/app/globals.css` ternyata berisi beberapa "lapisan" desain yang ditempel
bertumpuk dari waktu ke waktu (komentar V10, V12, V13, V14, lalu blok terakhir
"V27 CONTROLLED UI FOUNDATION"), tanpa lapisan lama pernah dibersihkan. Akibatnya:

- **Bug nyata yang bikin tampilan rusak:** blok "V27" menimpa `.form-grid` menjadi
  grid 12 kolom (`repeat(12, minmax(0,1fr))`) tanpa ada elemen manapun yang diberi
  `grid-column` span. Karena field form (login, buat admin, edit transaksi, dsb.)
  cuma `<label>` biasa tanpa span, tiap field jadi cuma dapat 1/12 lebar layar —
  hasilnya kolom form super sempit/berantakan di halaman admin, login, dan
  super-admin. **Sudah diperbaiki** jadi `repeat(auto-fit, minmax(240px,1fr))`
  (responsif otomatis, tanpa perlu class tambahan).
- **461 aturan CSS unik, tapi 502 blok ditulis** — 41 blok adalah duplikat murni
  dari selector yang sama (mis. `.form-grid`, `.card`, `.btn`, `input`, `.btn`,
  `.metric-grid`, dst ditulis ulang beberapa kali). Semua duplikat sudah
  digabung, mengikuti urutan cascade asli (nilai yang tampil di browser sekarang
  **tidak berubah**, kecuali fix `.form-grid` di atas) — jadi file jauh lebih
  pendek dan tidak ada lagi aturan yang saling menimpa tanpa disadari.
- File di-format ulang jadi multi-baris supaya bisa dibaca dan diedit manual ke
  depannya (sebelumnya banyak baris tunggal sepanjang puluhan ribu karakter).
- Set token warna ganda (`--bg/--text/...` lama dan `--ui-bg/--ui-text/...` baru
  dari blok V27) **dibiarkan berdampingan** karena blok V27 memang dipakai untuk
  fix aksesibilitas input di dark mode (`color:var(--ui-text) !important` supaya
  teks di form tidak putih-di-atas-putih). Menghapusnya berisiko mematahkan fix
  itu, jadi tidak disentuh — hanya konflik `.form-grid` di atas yang jelas-jelas
  bug dan diperbaiki.

✅ Sudah diverifikasi: `npm run build` (Next.js 16 / Turbopack) sukses tanpa error,
dan semua className yang dipakai di komponen React masih punya definisi CSS yang
sesuai setelah dedup.

## 2. Keamanan backend (`apps-script/Code.gs`)

Backend ini sudah cukup baik dari sisi keamanan dasar:
- Password di-hash (SHA-256) dan dibandingkan pakai `safeEqual_` (constant-time).
- Ada rate limiting/lockout setelah 5 percobaan login gagal.
- Akun Super Admin default **dipaksa ganti password** (`must_change_password: TRUE`)
  sebelum bisa dipakai — jadi hash default di source code bukan celah langsung.
- Role-based access (`requireSession_`, `requireSuperAdmin_`, `hasPermission_`)
  konsisten dipakai di `doGet`/`doPost`.

Yang diperbaiki:
- `DEFAULT_ADMIN_PASSWORD_HASH` adalah konstanta mati (dideklarasikan tapi tidak
  pernah dipakai di manapun) dan kebetulan nilainya sama persis dengan
  `DEFAULT_SUPER_ADMIN_PASSWORD_HASH` — membingungkan dan berpotensi salah pakai
  kalau ada yang menambah kode baru. **Sudah dihapus**, dengan catatan bahwa akun
  Admin biasa selalu dibuat dengan password unik lewat `createAdmin`, bukan default
  hardcoded.
- Ditambahkan komentar pengingat: segera login & ganti password Super Admin
  default setelah deploy pertama kali (`superadmin@tcc.local`).

Belum diaudit mendalam (di luar scope perbaikan CSS ini): validasi input di sisi
spreadsheet, batas ukuran upload bukti (`MAX_UPLOAD_BYTES` sudah ada — 8MB),
dan proteksi CORS pada endpoint Apps Script.

## 4. Update lanjutan (sesi ini) — navbar & dark mode

Ditemukan **empat breakpoint mobile-nav yang saling tumpang tindih dan berebut**
(`@media (max-width:820px)`, `@media(max-width:800px)`, dan dua variasi
`@media(...max-width:900px)`), masing-masing mendefinisikan ulang posisi/ukuran
tombol buka-tutup navbar (`.mobile-menu-button`), topbar mobile, dan animasi
sidebar dengan nilai yang berbeda-beda. Karena rentang lebar layarnya saling
overlap, browser memakai "siapa yang menang di urutan file terakhir" — hasilnya
tidak konsisten tergantung lebar layar persis, dan salah satu versi tombolnya
memakai warna putih hardcode (`background:#fff`, ikon `#344054`) yang tidak
menyesuaikan dark mode.

**Sudah digabung jadi satu breakpoint (`≤820px`)** yang konsisten:
- Tombol buka/tutup navbar sekarang pakai warna tema (`var(--surface)`,
  `var(--text)`) → otomatis menyesuaikan light/dark mode, tidak lagi kotak putih
  di dark mode.
- Topbar mobile diberi padding-kiri yang pas dengan posisi tombol, supaya teks
  brand tidak tertindih tombol hamburger.
- Sidebar overlay, backdrop, dan collapse-button sekarang konsisten di semua
  lebar layar ≤820px (sebelumnya bisa "lompat" di rentang 800–900px karena tiga
  sistem berbeda aktif bersamaan).

File preview interaktif (`tcc-ui-preview.html`) disertakan supaya perubahan ini
bisa langsung dicoba tanpa perlu login/backend — buka tombol buka/tutup navbar,
collapse sidebar, dan ganti tema langsung dari file itu.

## 7. Saran #1 & #2 — dikerjakan (typografi & warna jadi design tokens)

**#1 Skala tipografi**
Sensus ulang yang lebih teliti (termasuk shorthand `font: <weight> <size> <family>`
yang sebelumnya tidak ikut terhitung) menemukan **25 ukuran font berbeda**
dipakai di 158 tempat. Sudah dirapikan jadi **10 token skala resmi** di `:root`:

```
--fs-3xs:9px  --fs-2xs:10px  --fs-xs:11px  --fs-sm:12px  --fs-md:14px
--fs-lg:16px  --fs-xl:18px   --fs-2xl:24px --fs-3xl:32px --fs-hero:42px
```

Ukuran yang jaraknya sangat dekat dan dipakai tidak konsisten digabung ke
tetangga terdekatnya (mis. 13px→12px, 15px→14px, 20/21/22/25/26/28px→24px,
30/34/36px→32px) — beda visualnya minimal (≤4px, biasanya di judul/label
yang jarang dipakai berdampingan langsung), tapi kodenya jadi jauh lebih
konsisten. **156 dari 158 deklarasi berhasil dikonversi otomatis ke
`var(--fs-*)`**, sisanya 2 kasus format tak biasa diperbaiki manual.

Catatan: banyak teks besar (judul hero, angka saldo besar) di file ini
sebenarnya sudah pakai `clamp()` (fluid typography modern, otomatis
menyesuaikan lebar layar) — itu **tidak disentuh** karena sudah teknik yang
bagus, bukan bagian dari masalah.

**#2 Warna status di luar token**
10 warna hex yang paling sering diulang-ulang untuk badge/pill status
(hijau=sukses, ungu=aktif, merah=bahaya) — total 54 titik pemakaian tersebar
di file — sekarang **disentralkan jadi satu sumber kebenaran** di `:root`:

```
--success-text --success-strong --success-bg --success-bg-soft --success-border
--active-bg --active-text --active-strong
--danger-text --danger-bg
```

Kalau nanti mau ganti nuansa hijau/ungu/merah brand, cukup ubah **satu baris**
di `:root`, tidak perlu cari-cari di puluhan tempat lagi. Warna hex yang jarang
dipakai (1–3 kali, kebanyakan untuk elemen dekoratif spesifik) sengaja
**tidak** ikut ditarik jadi token — risikonya lebih besar dari manfaatnya
tanpa bisa dicek visual langsung.
